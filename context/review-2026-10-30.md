## B. Functional bugs (app would not do what it claims)

| # | Where | Problem | Fix |
|---|---|---|---|
| B1 | `ExpiryRepository.enqueuePurge` | **No `setInitialDelay`** — the purge worker runs immediately, so every "delete in 15 min" deletes instantly. This breaks the core TTL feature. | Delay = `deleteTimeEpochMs - now`, `ExistingWorkPolicy.REPLACE`. |
| B2 | `ExpiryRepository.upsert` | Worker receives `item.id`, which is 0 on first insert (rowid generated inside `insertOrReplace`) and *changes* on every REPLACE, so `findById(rowId)` misses → worker no-ops. | Worker looks up by `workManagerId` (stable per screenshot); add `findByWorkManagerId` DAO query. |
| B3 | Cancel paths (`ScheduledViewModel.cancel`, `CaptureActions.deleteNow`, bulk cancels) | DB row removed but the WorkManager unique work keeps running. | Repository cancel methods also `cancelUniqueWork`. |
| B4 | Reschedule flow | Re-scheduling the same screenshot inserts a *second* row (unique index is on workManagerId, ids differ per call) and `KEEP` policy leaves the old timer running. | Stable work id per screenshot (`snapttl_purge_<id>`), cancel-then-insert, REPLACE policy. |
| B5 | `ExpiryPurgeWorker` | (a) `media == null` → counted as FAILED even though the screenshot is already gone; (b) on FAILED it still deletes the queue row, losing the scheduled deletion forever. | media==null ⇒ success (cleanup only); FAILED ⇒ `Result.retry()` (cap attempts) and keep the row. |
| B6 | Overlay "Delete now" | Actually schedules a delayed deletion (first chip) instead of deleting now. "Share & delete" likewise mislabelled. | Delete now = `CaptureActions.deleteNow`; Share & delete = share then schedule (labelled). |
| B7 | `SearchViewModel.init` | Nested `collect` inside `collect` — every keystroke leaks another infinite collector (never cancelled). | `flatMapLatest`. |
| B8 | `ScreenshotRepository.deleteViaSaf` | `query(uri, projection, /*selection*/ null, /*args*/ arrayOf(name), null)` — args without a selection; also never matches subdirectories. | Real selection `COLUMN_DISPLAY_NAME = ?`; MediaStore fallback stays. |
| B9 | `CaptureMonitorService` ACTION_STOP | `startForegroundService()` + `stopSelf()` without `startForeground()` → `ForegroundServiceDidNotStartInTimeException` crash (API 26+ contract). | Call `startForegroundCompat()` before `stopSelf()` in the stop branch. |
| B10 | `LocaleHelper.apply` | `config.setToDefaults()` wipes uiMode/oration etc.; no activity recreate, so the language switch never visibly applies; pre-33 wrap missing. | API 33+ `LocaleManager.setApplicationLocales`; pre-33 `attachBaseContext` wrap + `activity.recreate()`. |
| B11 | Manifest | `INTERNET` + `ACCESS_NETWORK_STATE` declared although the app is offline-first with bundled ML Kit models. | Remove both; audit enforces the expected set. |
| B12 | Boot resilience | Rows whose WorkManager entries were lost never re-run. | `rescheduleAll()` reconcile at app start + BOOT_COMPLETED. |
| B13 | Overlay stacking | Duplicate `onChange` for the same URI launches the overlay repeatedly. | Debounce same screenshot id (5 s) in the service. |
| B14 | `Permissions.required` | Always lists `READ_MEDIA_VISUAL_USER_SELECTED` with a Grant button that can never be satisfied directly on Android 14 (only granted via "Select photos"). | Media group: full OR partial counts as granted; request both together. |
| B15 | Settings vs SPEC | Missing SAF screenshot-folder tree picker (needed for reliable deletion on 11+/14+), overlay permission row, advanced durations (30 s / 5 min / 30 min / 3 days) and the OCR index toggle. `indexAll` runs in the ViewModel scope instead of WorkManager (violates the repo rule that long work is WorkManager). | Add all of the above; `OcrIndexWorker` via unique work + progress observation. |
| B16 | Time chips | Chips stored as minutes (Int) can't express the original 30 s advanced duration; Home chips are dead buttons; free/premium gating not enforced on chip editing. | Seconds-based `domain/TimeChips` + entitlement gating + persisted selection. |
| B17 | `OcrIndexWorker`/SearchRepository | Failed OCR analysis still writes an (empty) index row, so the screenshot is never retried; deleted screenshots get re-indexed next pass. | Skip on failure; tolerate transient failures. |
